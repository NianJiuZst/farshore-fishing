# 1.4.0 Android 打包控制复核

本次 Android 打包沿用已经通过 Mac 端 37 套验收的游戏源提交 `1910dbd794a709f726aa192160d879a1eb145e8f`。后续打包修订仅涉及 `tools/` 中的 Android 检查、报告和回归测试，以及本说明；`game/`、`art_masters/`、既有截图和验收证据保持逐字节不变。

## 实际发现并修复的阻断

- unsigned verifier 的版本名称允许 1.4.0，但 versionCode 仍固定为 7。现在只接受明确审核过的 1.3.0/7 与 1.4.0/8 配对，并继续核对 APK、冻结源码和公开身份中的三个值。
- 本机手动签名助手仍固定检查 1.3.0、74 鱼、9 区域、18 钓点。现在按实际 APK 的受限版本配对检查：1.3.0 为 74 鱼、9 区域、18 钓点、5 档竿；1.4.0 为 110 普通鱼、1 个独立蓝鲸挑战、10 区域、21 钓点、6 档竿。鲸类的哺乳动物标记、禁用普通钓鱼和独立挑战类型均必须正确。
- APK 机器可读报告分别记录普通鱼类、所有目录物种、哺乳动物及独立挑战，避免把蓝鲸算作第 111 种鱼。

包名、原公开证书指纹、Vulkan/ARM64/API/16KB 对齐门槛、素材一致性与失败即停止规则没有放宽。检查测试使用惰性的模拟 Android 工具调用，不运行签名，不读取用户私钥或密码。

## 验证与来源链

针对修改执行 `tools/test_unsigned_handoff.py`、`tools/test_local_signing_inspection.py`、`tools/test_release_packaging.py` 及 `git diff --check`。最终构建报告保留具体数量、原日志、实际构建 commit、源码 ZIP SHA256 及每个 Git blob 的校验。

Mac 端既有 37 套游戏验收仍归属于原冻结源；它们没有被重新标记为 Linux 或 Android 真机测试。云端另外核对 67 个提交的 QA 证据副本及 10 张原生捕获图的 SHA256，并使用已有 Godot 4.6.3 / Android 36.1.0 工具链执行隔离导入、素材审计和 unsigned 导出。

unsigned 输入只进入专用的未发布交接草稿，不能作为正式 APK。用户在自己的 Mac 使用既有证书并手动输入口令后，云端再核对签名 v2/v3、证书、公包身份、16KB 对齐及签名前后每个 ZIP 成员的原始字节。只有验证通过的 signed APK 可以进入正式发布。

Android 16 / Snapdragon 8 Elite 的真实安装、1.3 覆盖更新、帧率、发热、物理触控和安全区仍需要真机验收。桌面截图、逻辑回归和 APK 静态检查不能替代这些项目。
