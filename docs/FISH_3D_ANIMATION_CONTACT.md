# Animated fish attachment acceptance

Static hero renders did not catch a visible tail gap in the first real game preview. The strengthened authoring gate now tags membrane and ray attachment vertices and measures their evaluated nearest distance to the deformed body over nine samples in each of four clips. The two kinds are recorded separately. The tolerance is4mm relative to a1m normalized resting fish, not a blanket world-space gap on all sizes. Jaws and gills, whose intended behavior involves opening, are not incorrectly counted as detached fins.

The gate found and blocked a14.4mm flatfish caudal-root placement gap and smaller dorsal/paired-root problems in other authored profiles. Roots were corrected against their actual body surface; the acceptance tolerance was not widened. Candidates are exported to per-species staging, validated, and atomically promoted only after success. Blender must run with `--python-exit-code 1` because its process can otherwise exit0 after a script exception.

Corrected olive flounder was also inspected in the actual production Main detail/result pages on desktop Godot Mobile/Vulkan, using an isolated seeded save. Six additional actual transparent-viewport swim frames each have a single substantial connected fish silhouette at alpha>32 (no detached tail/fin island above15 pixels). This supports the rendered correction in those sampled views; it is not a proof of all possible animation poses or Android-device performance.

Raw evidence: `build/qa3d/full_catalog_preview_corrected/`, `build/fish-preview/contact/`; per-species numeric reports are `ownbuild/fish3d-catalog/<species>/validation.json`. The final catalog audit must link these reports to exact canonical asset/master hashes so old reports cannot certify changed geometry.
