# 1.2.0：两种鱼的真实 3D 体验范围

本轮按用户确认只制作一个固定钓手、鲤鱼与鳄雀鳝两种真实3D鱼、一处管理型河湾试钓场。不是宣称既有44种鱼和12钓点已全部转成3D；扩展须等用户验收。

- `TrialFishery` 为无存档副作用的内容适配器。原44鱼JSON、6水域/12钓点、装备、解锁、统计与收藏均保留，不改写物种的自然分布。
- 试钓地点是明确标注的虚构管理型场所，记录ID为 `river_trial / river_trial_dock`。该设定不表示鳄雀鳝原产欧洲或亚洲，也不把旧湖岸钓获偷偷改名。
- 可在准备页选择鲤鱼、鳄雀鳝或混合目标，方便验收两套模型/动画，避免为了看到第二种鱼反复刷取。目标选择只作用于本次体验，不改写旧版已保存的旅行选择。
- 混合目标保留原四种饵料、时间和天气偏好。新增甜玉米、面团饵、鱼肉块与旋转亮片：前两种明显偏向鲤鱼，后两种偏向鳄雀鳝；这些是透明记录在 `EXTRA_BAIT_WEIGHTS` 的游戏平衡权重，不是实测摄食概率。试钓场不要求旧版旅行解锁或高阶装备；原有三款装备保留，追加两款有不同控线参数的鱼竿；五款装备均参与原有控线逻辑。
- 个体长度与重量仍经原 `EncounterGenerator.make_individual` 产生，沿用物种范围、锚点与体况变化。鳄雀鳝的短促冲刺是本次体验的游戏平衡选择，不是自然科学结论。
- 试钓钓获仍通过原 `SaveStore` 的唯一事务入口结算，旧统计、保护鱼记录、独立最大长度/重量、待处理鱼、收藏与设置均保留；不清空、不替换玩家存档。

`tests/trial_fishery_tests.gd` 单独验证内容边界、目录不变、旧保护记录与新试钓记录共存，以及真实磁盘重启后的状态保留。人物、鱼和镜头必须由实际Node3D/Camera3D、网格、骨骼和动画实现；PNG只继续承担普通界面图标和既有图鉴插画。

新增饵料在明确选择单一目标时不强行改掉目标物种；混合目标才体现鱼种吸引差异。回归测试遍历全部五竿、八饵、三种目标，并固定种子抽样检查新增饵料确有差异，原四饵权重保持原值。
