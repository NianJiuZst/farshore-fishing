## Why the previous assertions were obsolete

The user's `1afda37fa9fd8be23ff6d5cef1790a008a44f5f6` visual update is the design baseline. [LOCAL_OPTIMIZATION.md](LOCAL_OPTIMIZATION.md) explicitly describes consistent paper cards, input fields, focus borders, and large touch buttons. The earlier [UI_STYLE_TESTS.md](UI_STYLE_TESTS.md) borderless result is historical; its transparent-card/button expectations do not describe the current production source.

Before these assertion changes, running the existing tests against the unchanged production styles showed:

- Failure modal: **35 / 37**, exactly two failures, both requiring retry/dismiss to be `StyleBoxEmpty`; all input, layout, safe-area and modal-lifecycle assertions passed
- UI style: **15,731 / 18,001**, 2,270 failures: 2,160 transparent-button expectations, 50 obsolete world-caption outline expectations, 27 transparent-card expectations, 20 comparisons against paper despite a different actual button surface, 6 transparent-input expectations, 6 pictogram expectations on the intentionally text-only graphics-quality choices, and 1 held-button borderless expectation
- Neither pre-change run emitted engine `ERROR`, `SCRIPT ERROR`, or `WARNING` lines

This is source-backed test alignment, not a restoration of the old borderless design. The initial alignment diagnostic runs found 19 test-authoring issues at each size: 13 exact transparent-color comparisons used transparent white where Main explicitly specifies transparent black, plus the 6 graphics-selector exceptions. Those expectations were corrected to the actual upstream values before the final passing runs. No failed production behavior was hidden or skipped.

## Explicit current surface contract

Expectations are fixed independently in the tests; they are not generated by calling the same style builder being audited.

- `IconAction`: exact six-state `StyleBoxFlat` fill, border RGBA/width, 18 px corners (22 px primary), hover lightening, held-state darkening, disabled fill alpha, and no added shadow. Primary, normal, glass/light-label, and subtle variants have separate expected colors
- Focus on icon actions: exact transparent-center overlay, opaque `#d0ad64` 3 px border. Inputs and notebook tiles keep their exact opaque teal 2 px focus ring; the tests do not treat a filled or invisible focus overlay as equivalent
- Main input theme: exact pale normal and hover fills, 16 px corners, one-pixel borders, and transparent focus center. Base Button states and the deliberately empty inherited pressed/hover-pressed/disabled states of LineEdit/OptionButton must still be `StyleBoxEmpty`; transparency has not been dropped as a contract where it is intentional
- Cards: only the four actual upstream paper/specimen/glass fill variants are accepted, with 22 px corners, the exact subtle border, and their exact allowed symmetric content insets. The failure panel separately keeps its paper fill, 24 px corners, one-pixel border, and 16 px shadow with the correct offset
- Notebook tiles: exact discovered/undiscovered fills, hover/pressed colors, 20 px corners, one-pixel border, and transparent-center teal focus ring
- Captions: contrast is measured against the actual button surface, with translucent glass composited over white as a conservative bright-scene case. The existing unoutlined design is preserved. The numeric test uses 3:1 for authored font sizes at least 24 logical pixels and 4.5:1 below that; disabled controls retain their separate icon/text-opacity checks
- Graphics quality: only the three actual Settings choices (`省电`, `均衡`, `精致`) may use the intentional text-only variant. The check requires the real `_set_quality` callback bound to the corresponding quality, a three-child horizontal selector, zero icon extent, a centered 23 px full-button caption, and the exact selected/unselected primary/surface color pair. Other actions still require their icon or adjacent specimen illustration
- Native held Back input still must hover/press/focus the real control, change its visual feedback, retain the exact held surface, and invoke the actual Back callback on release

### Preserved accessibility limitation

The upstream gold focus ring on the pale `#e8eeea` surface has approximately **1.81:1** contrast, below a 3:1 non-text contrast target. Its exact opaque color, three-pixel geometry, clear center, and actual focus ownership are verified; that does **not** certify this focus treatment as meeting accessibility contrast requirements. The limitation was reported before changing assertions. The user's production style was preserved rather than silently recolored to obtain a different claim.

From the repository root, with the already imported runtime resources available:

```sh
for TEST in fishing_failure_modal ui_style; do
  for SIZE in normal tall; do
    D=$(mktemp -d /tmp/farshore-upstream-style-recheck-XXXXXX)
    mkdir -p "$D/home" "$D/data" "$D/config" "$D/cache"
    EXTRA=""
    if [ "$SIZE" = tall ]; then EXTRA="--tall"; fi
    HOME="$D/home" XDG_DATA_HOME="$D/data" XDG_CONFIG_HOME="$D/config" \
      XDG_CACHE_HOME="$D/cache" timeout 600 godot --headless \
      --audio-driver Dummy --path game --script "res://tests/${TEST}_tests.gd" \
      -- $EXTRA > "$D/output.log" 2>&1
    RESULT=$?
    cat "$D/output.log"
    printf '%s %s exit=%s log=%s/output.log\n' "$TEST" "$SIZE" "$RESULT" "$D"
    test "$RESULT" -eq 0 || exit "$RESULT"
  done
done
```

Each run uses its own HOME/XDG directories. The UI harness refuses unisolated user data. No import, export, signing, production-save access, or network request is part of these commands.
