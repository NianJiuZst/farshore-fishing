# 本地存档与钓获事务验证

## 实现与接口

实现：`game/scripts/save_store.gd`，`SaveStore extends RefCounted`。所有关键事件经过此模块。每个存档目录只创建一个游戏内 `SaveStore` 实例；同步调用由互斥锁串行执行，模块不使用异步写入，也不支持两个游戏进程同时修改同一目录。

与 `docs/CONTRACT.md` 的接口一致：

- `initialize(optional_root = "user://") -> bool`：新建或读取存档；返回失败时读取 `error_message`。若两份文件均损坏或发现更高 schema，进入 `read_only`，不会用默认状态覆盖文件
- `state: Dictionary`：返回深复制快照，修改读取结果不影响内部状态。请修改快照后调用 `commit_state(snapshot)`，不要试图直接修改 `store.state["..."]`
- `error_message: String`、`status_message: String`、`read_only: bool`：分别用于本次错误、初始化/恢复说明和保护模式
- `begin_session(session_id)`、`abandon_session(session_id)`：当前只允许一个活动会话；逃脱、放弃时结束会话。进程重启后没有活动会话
- `settle_catch(record) -> Dictionary`：返回 `{ok,error,new_species,new_length,new_weight,duplicate}`。重复成功回调返回 `ok=false, duplicate=true`，不给第二次奖励。过期会话返回失败。成功才清除活动会话
- `dispose_catch(catch_id, "sold" | "released") -> Dictionary`：返回 `{ok,error,duplicate}`；出售增加该记录的 `sale_value`，放生增加 8；成功后移除待处理项。不存在的项目和重复处理没有货币或统计副作用
- 保护观察记录的 `release_only=true` 由事务层强制执行：任何 `sold` 调用均返回明确错误，不进入磁盘写入，不改变待处理鱼、统计、货币或 revision；即使该记录带有伪造的非零售价也不能出售。放归仍为一次性的普通 8 旅币奖励，保留发现与历史纪录，不产生出售收益
- `commit_state(candidate) -> bool`：购买、旅行解锁、收藏和设置等唯一写入口；先验证与写入，成功后才发布内部状态
- `total_count() -> int`：由各物种 `catch_count` 求和；没有维护另一份总数
- `discovered_count() -> int`：统计 `catch_count > 0` 的唯一物种

新增一个兼容字段 `save_revision`，默认 0，每次成功事务递增。`commit_state` 要求输入携带当前 revision，防止旧界面快照覆盖刚完成的交易。只要从 `state` 读取完整快照，该字段自动携带，不需要界面维护。

`catch_id`、`session_id` 与内容 ID 限长 128，允许 ASCII 字母、数字、下划线、连字符、点和冒号；每次抛竿使用新 ID。长度和重量保存为整数毫米/克。JSON 中的数值在读取后规范化；不会把解析器产生的浮点装备 ID 与整数 ID 错误区分。

### 数据与边界

- 每个物种独立保存累计次数、首条、末条、最长个体完整快照、最重个体完整快照及分区次数。最长与最重可以来自两条不同的真实鱼，平纪录保留旧纪录
- 保存失败不改变内部统计、奖励或待处理鱼；保留本轮原始结果，只允许原样重试，不能改尺寸后重试或直接换到下一会话。明确 `abandon_session` 才丢弃尚未成功保存的结果
- 待处理鱼最多 64 条。达到上限时拒绝新的结算并提示先处理待处理鱼，不自动出售、放生或删除。释放一个名额后原会话可以重试
- 最近成功的 `catch_id` 最多 256 条。更早的 ID 离开去重窗口后，仍无法通过当前会话身份检查；成功过的会话已终止，重启也不恢复未完成会话
- 收藏最多 6 个已存在物种引用；收藏、预览、出售和放生不会增加或减少历史数量
- 数值、JSON 类型、ID、引用、分区次数、列表上限和 8 MiB 文件大小会被校验。读取不实例化场景、不加载存档指定的脚本、不执行任何存档字符串

## 写入流程与恢复语义

文件均在同一个指定的本地目录：`save.json`、`save.backup.json`、`save.tmp.json`、`save.backup.tmp.json`。

1. 校验候选状态及当前文件版本；拒绝未知更高 schema
2. 将完整候选写入同目录临时文件，刷新、检查 I/O 错误、关闭后重新读取；验证精确文本及解析后的状态
3. 若现有主文件有效，复制到备份临时文件并核对文本，检查重命名结果后更新备份。若正在从有效备份恢复，不用损坏主文件覆盖备份
4. 如即将替换损坏文件，先保存独立 `.corrupt-时间戳-编号` 副本，核对内容；保存失败即停止，不覆盖原件
5. 检查临时文件到正式文件的同目录 rename-over-existing 返回值；不会用“先删除正式文件，再重命名”的危险兜底
6. 重新读取正式文件，验证完整状态，之后才发布内存中的新状态

这是经检查的替换流程，**不宣称所有系统上的原子性，也不宣称突然断电后的 fsync/目录持久化保证**。Godot 的关闭操作没有独立错误返回值；写入/刷新后的错误和关闭后的重新打开校验共同覆盖可观察的失败。若替换后读回结果不确定，模块切换为只读并提示重启核对，避免盲目继续写入。

有效备份通常是上一次成功提交的主文件，因此恢复时可能少最后一次提交；恢复信息会明确说明。首次创建同时建立初始备份。孤立临时文件不自动当作已提交存档恢复。

主存档损坏时读取有效备份，原损坏文件先留在原位；下一次写入之前再复制留证。两份都不可用时保留两份原件、初始化失败并锁定写入。主文件或备份任一出现未知更高 schema，均保护所有文件；运行过程中也重新检查版本。

Schema 1 到 2：补充缺失的默认设置、选择、待处理、去重、装备等字段；物种 `count` 迁移为 `catch_count`，`region_counts` 迁移为 `regions`；保留已有完整纪录、收藏与货币。迁移首先在内存进行，下一次正常事务才写入 schema 2，并把原 schema 1 主文件保留为备份。已有物种不依赖当前内容目录重建，因此新增物种不会抹除旧统计。

扩展内容继续使用 schema 2。钓获快照可选字段 `release_only`（JSON boolean）与 `conservation_note` 原样保留到待处理项、首条、末条、最长和最重纪录；缺少该字段的旧记录不被改写为新格式，原有出售行为不变。中华鲟相遇属于游戏内虚拟保护观察，不构成现实捕捞或垂钓许可。

## 自动化覆盖范围

所有业务断言直接调用生产 `SaveStore`，测试没有复制另一套结算算法。

- 连续三条同种鱼准确计数；首次发现标志、跨地区累计和分区数量
- 第一条、最后一条、最大长度、最大重量的完整且独立快照
- 重复回调、旧会话、无效钓获、逃脱、重启后的旧结果不计数
- 出售、放生、交叉重复处理均幂等，历史次数不变
- 收藏、展示读取、装备、解锁、设置和游戏时间保存并重启恢复
- 待处理鱼重启后可继续处理；重启不重放历史奖励
- 状态读取隔离；过时 `save_revision` 拒绝覆盖
- 临时文件写入失败、写入后截断导致校验失败、备份重命名失败、正式文件重命名失败；每项检查内存与主存档未发布候选、错误可见、原样重试恰好计数奖励一次
- 出售写入失败保留鱼，重试恰好收益一次
- 保护观察记录在结算和放归各自的四项真实 I/O 故障边界下均可原样重试；改掉保护标记的重试被拒绝。直接出售、重启后出售、放归失败改售、已放归后再处理均不会产生出售收益或重复奖励；历史完整快照和 optional boolean 类型经读回验证
- 主文件损坏从备份恢复；损坏文件字节保留；两份损坏都保护
- 超大未来版本号出现在主文件或备份均保护；游戏运行中外部文件升级也阻止写入
- Schema 1 迁移、缺字段默认、保留原版备份、追加新物种与重启
- 孤立临时文件不冒充正式事务
- 64 条待处理上限拒绝第 65 条且不丢弃任何鱼，释放名额后允许重试
- 10,000 次结算及放生，次数、货币、去重窗口和状态大小均检查；老 ID 确实离开窗口后仍被会话门禁拒绝

10,000 次压力循环只用测试子类替换磁盘提交为内存成功应答，生产统计、会话、校验、事务发布及处理逻辑完全不变；目的是验证状态有界而非模拟 20,000 次真实闪存写入。循环结果最终交由未修改的生产磁盘 writer 写入、读回并重新实例化校验。常规事务、故障、备份和迁移测试始终使用真实临时目录 I/O。
