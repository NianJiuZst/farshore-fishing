# Beta 3 UI research and independent audit

Reviewed 2026-10-03. Baseline: `8bd027433c705ecdf26e105b1286864a6366caa3` (beta 2 production UI), before beta 3 integration. This audit covers hierarchy, touch behavior, content density, and navigation; it does not certify Android hardware performance.

## Evidence and scope

- Inspected the actual pixels of the supplied `1000049902.jpg`: empty-cast content occupies roughly the upper quarter of an otherwise opaque, empty screen. The 3D fishing context disappears for a minor recoverable event.
- Rendered 15 actual production screens with Godot 4.6.3 Mobile Vulkan on desktop Mesa/lavapipe, at 720 × 1584. The run used a private X display, isolated HOME/XDG folders, and labeled synthetic save fixtures. No player save was read or changed.
- Local, ignored evidence: `build/beta3-ui-audit/baseline/`, `baseline-contact.jpg`, `baseline.log`, and `capture_baseline.gd`. Screens include home, preparation, travel, gear, undiscovered/partially discovered catalog, undiscovered/known species, record section, empty favorites, settings, idle/fight HUD, empty cast, and catch result.
- Input reproduction: screen-touch down/up at the fish image center leaves `_screen == "catalog"`; mouse down/up there also stays in catalog; screen-touch on its title opens `_screen == "species"`. This confirms an entry-target defect, rather than absence of species details.
- Three legitimately settled fixture catches yield count 3; longest snapshot `audit_0_catch` (650 mm / 3800 g), heaviest `audit_1_catch` (550 mm / 4400 g), first `audit_0_catch`, latest `audit_2_catch` (600 mm / 4100 g). Existing SaveStore already maintains independent snapshots correctly. Do not replace these with species-range estimates or conflate the longest and heaviest fish.
- The baseline process completed. Its teardown printed resource-leak warnings; capture results are useful visual evidence, not a clean full-suite acceptance result.

## Prioritized production defects and design decisions

| Priority | Current evidence | Concrete change and acceptance condition |
|---|---|---|
| P0 | `_fishing_ended()` sends escape/empty-cast through `_open_page()`, whose solid `edf2e5` ColorRect covers all 3D pixels | Use a content-sized centered popup with restrained scrim; keep scene recognizable around it. One title, short cause, brief actionable hint, one primary illustrated action. No full-page heading/back chrome. Back/dismiss/retry must return to the same playable location without double settlement or stray held input |
| P0 | `_fill_catalog()` creates passive fish art and makes only the title a Button | Make the entire fish tile, including art and whitespace, one transparent hit target. Retain vertical drag cancellation. Test touch and mouse on image, title, and tile edges; drag over each must scroll without opening |
| P0 | `_show_species()` places all catch records after description, morphology, full location list, and bait copy; known-carp records start near the bottom of a tall viewport | Lead with photo, name, scientific name, then a compact “my catches” summary: count, longest, heaviest, first, latest. Follow with accurate natural-history introduction and game location/bait guidance. Zero catches must show zero and explicit absent records, never fabricated numbers |
| P1 | `_show_result()` leaves a large vertical void between specimen/measurements and fixed bottom actions on tall screens | Keep fish, ruler, measurements, record/reward summary, and sell/release decision in one cohesive content group. Use a bounded result presentation or intentional vertical centering that adapts to short and tall screens; preserve anatomical ruler endpoints and always reachable disposition controls |
| P1 | `_show_gear()` stacks five expanded rods before any bait choices; the initial tall screen still cannot reach bait | Expose equipped/borrowed rod and selected bait first. Add clearly labeled rod/bait navigation or compact sections so changing bait is a short action. Avoid repeating full-size rod art and 96px action rows when a compact selectable row conveys the same state. Owned, equipped, borrowing, and unaffordable must be distinguishable in text |
| P1 | `_show_catalog()` fits search, region, discovery, and sort in one row; most controls have no visible grouping or editing cue | Give search its own width and arrange the three filter/sort controls on a second row or responsive wrap. Show active criteria and a clear reset affordance. Preserve query, filters, sort, and scroll position after species detail/back |
| P1 | `_show_favorites()` renders six repeated hearts, six “add” actions, and six identical hints when empty; populated image areas are also passive | Use one meaningful empty-state explanation and one action. For populated favorites, use the same full-tile entry affordance as catalog, with true count/record summary. Returning from details must return to favorites, not unexpectedly catalog |
| P1 | HUD text is superimposed on bright sky/water and patterned wood; baseline idle and fight hints sit directly over planks; active state has only a small hint and action label | Keep the center water/float region clear. Group weather/location at top; retain accessible illustrated controls at edges. Make stage instruction, bite cue, tension/progress and main action readable at a glance. Use local shadow/outline or subtle localized gradient where needed, with no blanket dark panels |
| P1 | `_show_home()` gives the main action limited emphasis; its rod art visually overlaps scene objects and competes with the busy lower scene | Give “start fishing” a distinct visual anchor in the lower safe area, larger than secondary actions, while preserving the actual animated 3D scene. Add a concise selected spot/loadout/progress summary only if it helps the next choice. Do not introduce decorative slogans or a text-heavy dashboard |
| P1 | `_show_travel()` presents repeated 285px scenic images, full-width spot actions, and little distinction between current/available/locked; disabled unlock cost fades heavily | Preserve destination imagery but tighten the relationship among destination, discovery progress, selected spot, equipment access, and unlock cost. State the unmet requirement explicitly. Make current spot visually/textually clear and keep travel consistent with preparation |
| P1 | `_show_settings()` interleaves toggle actions, unlabeled slider value, game clock explanation, storage explanation, pending action, version, technical credits, and licenses | Separate sound/haptics controls, game/save information, and About/licenses. Show volume value and recognizable switch state. Put long attribution and implementation details behind About/license disclosure; keep user-facing data-loss information accessible |
| P1 | `_handle_back()` sends both species and zoom to catalog, irrespective of entry point; `_close_page()` uses broad lobby/fishing context | Give detail/zoom/settings a reliable return destination. Verify favorites → species → zoom → Back twice, result interruptions, settings from pause, and filtered catalog → detail → Back. Repeated Back must never silently abandon a pending catch |
| P2 | `_text()` uses the same outline strategy on clean opaque pages and scenery; small accent labels have weak base contrast | Separate paper-page text treatment from scene-overlay text. On solid `edf2e5`, computed base contrast is INK 9.23:1, MUTED 4.24:1, GOLD 3.50:1, TEAL 4.26:1, CORAL 1.66:1. Use darker colors for small text and especially save errors; gold is a selective accent, not the default body label |

All controls should retain borderless illustrated icon + text styling. A bounded light popup surface is appropriate for a dialog; it does not justify rectangular plates behind every action. Keep transparent hit areas generously sized even where the artwork is smaller.

## Primary-source research and actual pixel observations

1. [Fishing Planet developer diary, 2 June 2026](https://fishingplanet.com/devdiary-back-to-basics/) and its [official Lone Star map image](https://fishingplanet.com/wp-content/uploads/2026/06/lone_star_map.jpg). Opened and visually inspected the image in the cloud browser. The map dominates; a compact adjacent information region gathers destination, conditions, fish collection, and one departure action. Selected map point and departure action share a clear accent. Apply the hierarchy and task grouping to travel, without copying its dense desktop navigation or dark rectangular surfaces. The diary also explicitly discusses item search and category filtering in inventory.
2. [Fishing Planet Android listing](https://play.google.com/store/apps/details?hl=en_US&id=com.FishingPlanetLLC.FishingPlanet). Inspected the publisher's globe/travel screenshot pixels. Current destination is accented on the globe, the selected destination facts remain together, and the travel action is in the same decision region. This supports a persistent selected destination/loadout summary. The listing screenshot is an illustration of shipped/publisher-presented UI, not proof of every current mobile behavior.
3. [Fishing Clash Android listing](https://play.google.com/store/apps/details?hl=en-US&id=com.tensquaregames.letsfish2). Inspected multiple publisher images at their actual supplied size in the cloud browser. Several are promotional composites, so they cannot establish interaction behavior. The scene image with top resource/status strip leaves the lake and tackle unobstructed; useful principle: keep persistent information compact and at edges. Do not copy marketing slogans, currencies, or monetization clutter. The publisher's instructions place cast at bottom-right and tension at top-center, demonstrating deliberate separation of the thumb action and monitoring region.
4. [Android accessibility guidance](https://developer.android.com/guide/topics/ui/accessibility/apps). It recommends at least 48 × 48 dp touch targets, 4.5:1 small-text contrast and 3:1 large-text contrast, and semantic action descriptions. Application here: retain large invisible targets for borderless artwork; make the fish tile one target. A 96px logical Godot target is the project's current reference, not automatically certified as 48dp on every device; check actual Android density/scaling.
5. [Android dialog guidance](https://developer.android.com/develop/ui/compose/components/dialog). Dialogs occupy a layer above the main content, with explicit title, content, actions, and dismissal handling. Adapt the pattern to native Godot: content-sized container, background visible, intercepted background input, deterministic dismissal. No need to adopt Compose or Material's visual skin.
6. [Android edge-to-edge guidance](https://developer.android.com/develop/ui/views/layout/edge-to-edge). Inset handling must protect tappable controls from system bars, display cutouts, and gestures. Keep full-bleed scenery, but apply safe insets to all four sides of page/modal/HUD actions and inspect short/tall viewports plus actual Android system-bar modes. Desktop rendering cannot verify phone cutouts.

External game images were viewed for research only. They were not added to source assets or copied into the product.

## Final review gate

Review beta 3 runtime pixels independently after integration: home, preparation, travel (locked/current), gear (rod/bait), catalog (zero/known/filtered), species (zero/multiple independent records), favorites (empty/populated), idle/bite/fight HUD, empty/escaped popup, normal/protected/save-error result, pause, settings/About. Include 720 × 1280 and 720 × 1584, touch-image entry versus vertical drag, and Android Back chains. Report visual clipping, ambiguous controls, actual record mismatches, or unnecessary empty surfaces; structural tests alone do not establish visual quality.

## First integrated visual review

The first beta 3 integration was rendered at 720 × 1584 with 3D enabled throughout. Evidence is in `build/beta3-ui-audit/after-tall/` and `after-tall-contact.jpg` (19 screens). These files intentionally preserve the first pass, including defects found; they should not be presented as final release screenshots.

Verified improvements:

- Production screen-touch and mouse input on the fish image both open species details. The former image/title mismatch is fixed.
- Favorites → species → zoom → Back → Back returns to favorites in an actual runtime assertion.
- The empty-cast screen was reached from `session._finish(false, reason)`, not a standalone component preview. A roughly 596 × 364 light popup sits over a recognizable real 3D fishing scene. The opaque full-screen blank page is gone.
- Known-species view visibly shows actual count 3, longest 65.0 cm, and heaviest 4.40 kg near the photo. The lower record section retains four separate fixture snapshots.
- Catalog filters, bait grid, preparation, settings, favorites, and result have clearer grouping. Full-size inspection found no text/image clipping in the sampled content. Catch disposition actions now follow the specimen and records instead of being isolated at the bottom of the tall display.

Regressions/gaps sent back for correction:

1. **Home counter wrapping, release blocker:** the new right-side currency and discovery labels collapse to one character per line (`120` becomes three rows; `0 / 44` four rows). `after-tall/home_zero.png` is the direct evidence. Set a real minimum width for that group and disable numeric label wrapping, then re-render both aspect ratios.
2. **Settings return context:** code review found that rebuilding after a toggle or returning from About loses the Pause return origin. A persisted settings return target was subsequently added; the first tall capture predates that correction. It needs a runtime Pause → Settings → toggle → About → Back → Back check.
3. **Exit confirmation consistency:** lobby exit remained a full-page question with two actions. Use the same bounded scene-backed dialog pattern and verify cancellation/Android Back.
4. **Terminal HUD copy:** beneath the empty-cast popup, the paused HUD says that the fish/tension/time are preserved and still shows “reel,” despite the cast having ended. Suppress or neutralize transient instructions during the terminal modal while keeping the 3D scene.

## Final reviewed pass

The next integrated pass completed with exit code 0. `build/beta3-ui-audit/after-short/` contains 23 captures at 720 × 1280 plus corrected home and exit-dialog captures at 720 × 1584 (25 images total). `after-short-contact.jpg`, `after-short.log`, and `capture_after_final.gd` document the run. The renderer remained Godot 4.6.3 Forward Mobile / Mesa lavapipe with 3D enabled and isolated test saves. It still printed seven texture-RID warnings on process teardown; no script error or assertion failure occurred.

All four first-pass findings above were corrected and reviewed:

- Currency and discovery counts are legible single lines in both short and tall home screenshots.
- The actual Pause → Settings → toggle → About → Back → Back sequence asserts a return to Pause.
- Lobby exit is a compact light dialog over the 3D scene at both heights. The first-pass full-page confirmation is gone.
- Empty-cast modal hides the stale HUD instruction/action while retaining the visible scene. The production failure flow still originates from `session._finish(false, reason)`.

The final run repeats and passes fish-image screen-touch/mouse entry and favorites → species → zoom → Back → Back. The independent count/longest/heaviest/first/latest fixture values remain intact. Full-resolution visual inspection covered the catalog, species details, home, HUD, bait choices, regular/protected/save-error result, and both dialogs, in addition to the all-page contact sheet.

At 720 × 1280, the protected Chinese-sturgeon result visibly includes its release action and record-retention note within the viewport. The ordinary catch result's actions also remain in view. The save-error presentation has readable dark-red copy and a reachable retry action. Its error text is deliberately labeled as a screenshot fixture; this review does not claim fault-injected filesystem retry validation. The fixture's release path preserves actual notebook records.

No blocking clipping, overflow, misleading record values, or loss of modal scene context remained in the inspected final samples. The final tall home capture follows a viewport resize and scene-mode change; dynamic scenery may be caught during its transition, so use it as evidence of UI layout, not as a posed scene-art benchmark. Android cutouts, device density, hardware performance, complete 44-species visual coverage, and exhaustive interrupted-input behavior remain the responsibility of the release/device and behavioral suites.
