# 1.4.1 · 透明图标与长江钓点修复

本轮基于已发布的 v1.4.0，提交 `f4a487851c39ff2134ed04a157a37c61314a8059`。当时 `main` 仍指向 1.3.0，未把旧主分支当作新版起点。目标版本为 1.4.1 / versionCode 9，保留 110 种普通鱼、独立蓝鲸挑战、10 地区、21 钓点、6 竿和 12 饵。

## 交互和可读性

- 大厅、旅行、行囊、图鉴、收藏、设置、暂停、返回、抛竿与收线入口使用透明图标。点击区域与图像分别布局，保留至少 96 像素的触控高度、辅助功能名字和提示文字。
- normal、hover、pressed、hover_pressed、focus、disabled 六态均不绘制背景色块。焦点保留细描边；按压和禁用反馈由图标变化表示。
- 页面、物种卡片、列表、原生选择菜单、确认/失败弹层和蓝鲸界面移除色块底。说明、鱼名、价格、图鉴资料和可能影响存档的操作名称仍保留；以字形描边、阴影、间距和真实场景的轻微模糊改善阅读。
- 蓄力、张力、收线进度和蓝鲸的目标区间继续绘制语义条带。它们表达当前玩法状态，并非按钮或文字卡片的装饰背景。

## 两个缺陷与修复

`yangtze_estuary` 原船位 `(0, 0, -40)` 正落在中央沙洲内。原有近、中、远落点约在区域坐标 z=-47…-52；沙洲网格范围约为 x=-11.34…7.34、z=-57.60…-24.88，实际截图中沙面遮住浮漂。船位改为东侧水道 `(14, 0, -40)`，并增加使用导入 GLB 三角网格的水域查询，检查浮漂及漂移范围、浸没空间和读漂视线。无效请求先搜索同距离方向，再搜索较远水域；完全无解时拒绝抛投，不消耗一次钓鱼流程。舞台与环境的坐标变换共同参与查询。

`yangtze_river` 的准备和静候画面并不遮漂；真实遛鱼达到约 95% 时，站立岩岸过长的水侧部分覆盖了近端读漂区域。仅缩短该钓点岩岸的 z 方向尺寸至 0.60，保留站立高度，不修改共享相机。修复前后均通过实际咬钩、提竿和控线流程抓取同阶段截图。

抛投终点接触当前波面，遛鱼浮漂也使用与水体相同的波浪高度公式。原读漂信号、咬钩规则和存档模块没有改动。

原生 Mobile/Vulkan 抓取全部 21 钓点的准备、近/中/远抛和长屏画面，连同主要页面共 112 张；另有 13 张长屏/原生弹出菜单、7 张蓝鲸和 4 张真实遛鱼阶段截图。逐一查看了 21 点中抛的中心浮漂区域，并重点检查长江近/远抛、遛鱼末段、图鉴菜单和主要页面。脚本分别为 `tools/capture_ui_water_revision.gd`、`capture_clear_ui_extras.gd`、`capture_yangtze_fight.gd` 和 `game/tests/blue_whale_ui_tests.gd`。

主截图均来自真实游戏帧缓冲，不是设计稿。v1.4.0 页面/抛投基线采用 macOS Mobile/Metal；最终 after 与前后实战遛鱼均采用 macOS Mobile/Vulkan。因此 UI/抛投前后颜色不用于像素等价判断。所有截图只使用合成档案；全钓点抛投的鱼类记录固定为控制变量，不是该地点物种分布的证明。

本次通过结果包含明确的重跑：旧海洋 UI 测试仍要求显示已按需求隐藏的鱼饵标题；改为检查隐藏标题、准确辅助名字与保留触控区域后整套通过。首次该测试还在版本文件变动期间触发源码稳定性检查，冻结后重跑通过。水域测试最初把平板物理尺寸当作逻辑视口归一化，修正测试坐标后通过；生产相机未因该测试修改。Python 临时目录测试也改为使用 macOS 实际路径，生产工具仍拒绝用户传入的符号链接。原始失败结果留在本地调试目录，公开机器摘要记录这些重跑原因。
